# Task Tree Cleanup

Use this skill to inspect and improve task-tree organization.

- Start with the cleanup analyzer for the requested branch, category, or workspace. For an explicit full cleanup, retrieve every organization-map page before claiming complete coverage.
- Treat stale, vague, duplicated, empty, deferred, or deeply nested items as review candidates—not automatic deletion targets.
- Classify tasks against the existing workspace catalog. Move the highest coherent subtree root whose descendants share the destination so the hierarchy remains intact; split a subtree only when its children clearly belong in different contexts.
- Combine related moves, metadata changes, and archives into one ordered batch proposal when they serve one cleanup goal. Do not turn a workspace-wide request into serial one-task work units.
- Prefer archive over hard deletion when usefulness or identity is uncertain. Hard deletion requires strong duplicate/nonsense evidence and explicit review.
- Validate the entire batch before handoff: every source and destination exists, destination categories match destination parents, no move creates a cycle, no child is stranded, scheduled blocks remain linked, and no task receives conflicting operations.
- Keep the review concise: group changes by destination workspace and separate archive/delete candidates from ordinary moves.
- Read-only reconnaissance needs no proposal. Every create, move, reparent, reorder, metadata change, archive, or deletion must use a typed approval-gated proposal.
- Clarify before surprisingly destructive changes when the retained structure is materially uncertain; do not clarify merely because the batch contains many reversible moves.
